- SQL is composed of three components—a DML, DDL, DCL
- Each accounts for a different type of operation SQL supports
- Data Manipulation: basic INSERT, SELECT, UPDATE syntax
- Data Definition: Schema definitions for tables, indices, views
- General execution order: FROM -> WHERE -> SELECT
- Queries boil down to FROM, WHERE, and SELECT.
- An efficiently executed WHERE clause using an indexed column speeds up query execution, whereas a SELECT statement helps reduce memory footprint and data transmission size
- SQL by default allows duplicates, can be made into a classic set using DISTINCT
- Relational algebra uses sets where there are no duplicates whereas SQL uses bags
- Aggregates take a bag of tuples and return a single scalar value
- PLOP -> Parsing, Logical plan, Optimization, Physical operators
- You cannot compute averages as part of WHERE as functions that collapse rows into single scalar values are restricted to clauses that operate after rows have already been grouped. WHERE is a filtering mechanism—it's deciding whether to keep a row rather than computing an average.
- The way around this is a subquery that evaluates the average first
- In `COUNT(1+1+1) where c.id='519'`, the expr in COUNT has no bearance on the filter being applied. The WHERE clause applies filtering, and then COUNT(expr) returns the # of results that evaluate to non-NULL. Since a constant is never null like in `1+1+1`, all filtered rows contribute to the final count.
- COUNT(expr) operates on an expression that if is not null, contributes to the count. Unlike with WHERE/HAVING where only NOT NULL && NOT FALSE are both satisfied.



Definitions:
- SELECT is a projection, while WHERE is a selection
- WHERE filters horizontal records while SELECT shapes the vertical structure.
- "Projection" is a mathematical terms that maps a high-dimensional object into a lower dimensional space
- An attribute is a column or field part of a relation.
- A primary key specifies a one or more attributes that uniquely identifies a relation
- A foreign key establishes a cross-table consistency rule. It essentially prevents dangling pointers between tables
- The form `foreign key (Ak1, Ak2, …, Akn) references s` says that "this foreign key must match the primary key of `s` as a whole"
